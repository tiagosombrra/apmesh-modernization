## Native original-source input and independent method

The pipeline compiles the original serial C++ GeneratorAdaptive with existing default-OFF observation controls, executes **original Eistute and Book native research model runs in the same native CI job** and audits their genuine global postcommit `accepted_step_1_outer_1.ndjson` snapshots. Only genuinely globally accepted step `[1]` is present for each respective original model. Neither an Adapter local selected fallback, a staged P1/QUAD candidate, nor a second process with changed source parameters is allowed as a second accepted epoch.

The V5.2 **Python exporter** `tools/mesh_studio/native_accepted_vector_publication.py` re-runs `native_accepted_scene.generate_original_scene_bundle(original_directory)`, which independently reopens original source C++ postcommit raw NDJSON and source-bound reports and validates original patch/curve/native corner identities. It then checks this newly rederived source bundle exactly equals the same-run C++ scene JSON already published at R2.7.20 before exporting. A user-supplied JSON file alone **cannot attest C++ source**. 

The SVG renderer uses each **actual original triangle's three native UV doubles** per source patch, without grouping two distinct C++ node owners on the basis of equal XYZ and without fabricating UV between patches. All faces are emitted exactly once. Its **per-face native keys** are `(accepted_step, patch_slot, element_slot, native_element_id)` and all three original node IDs and UV are retained in SVG data attributes. Only genuinely observed native curve sample **vertices** are marked on the plot, *not fabricated continuous curves*. A separate independent `audit` CLI mode reopens the original C++ bytes and checks every SVG per-face native identity and original UV double numeric value, all patch inventories and sampled-marker count, all figure SHA-256s and deterministic output bytes. Raster, scripts, remote references, font downloads, false welding and claimed LOD are disallowed.
