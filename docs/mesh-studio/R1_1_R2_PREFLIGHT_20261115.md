# Mesh Studio — R1.1 interactive coherence and R2 transport preflight

Date: 2026-11-15. Isolated research frontend branch:
`feature/mesh-studio-fixture-first-20261114`. This increment does **not**
modify APMesh C/C++, QUAD scientific selection, `quad-templates`, or `main`.

## R1.1 implementation

- One vtk.js rendering context per source geometry and space (XYZ / UV). TRI,
  QUAD and edge filters update existing polygon/cell arrays without resetting
  the camera. Original source face IDs survive layer filtering and picking.
- Both viewports highlight the same selected source face. The selected overlay
  contains only its 3/4 corners, avoiding duplicate point arrays for the
  entire mesh. Picking rejects pointer drags over 5 screen pixels.
- `apmesh.meshstudio.web_camera.v1` stores two finite, nondegenerate camera
  poses in browser-local storage, with the original OBJ SHA-256 as its key.
  Invalid, nonfinite, mismatched or missing recipes are rejected.
- The Windows bootstrap `tools/mesh_studio/web/scripts/start-windows.ps1`
  explicitly requires the Windows Python launcher `py.exe -3.13`, creates
  `web/.venv-science`, and does not install into MSYS2/UCRT64. It starts both
  services on loopback, never exposes a public API, and retains Qt only as an
  independent historical optional diagnostic.

## R2 preflight — bounded binary transfer

`apmesh.meshstudio.geometry.bin.v1` is a little-endian rendering-only wire
format. Header: `APMSH001` (8 bytes), then 4 `uint32`: metadata byte length,
point count, cell count, total polygon words. The header is followed by bounded
canonical JSON source metadata, 3 floats per point (`float32`), indexed VTK
legacy polygon words (`uint32`), source face IDs (`uint32`), and a byte per
face for arity 3/4. The total is capped at 32 MiB; metadata at 4096 bytes.
Exact original source face IDs, TRI/QUAD typing, UV corner duplication and the
OBJ source SHA are preserved, and the verified JSON endpoint remains for
independent comparison. Float32 values are **never** fed back into the scientific
metrics or treated as an exact source geometry.

The browser now requests binary geometry and refuses malformed dimensions,
NaNs, duplicated face IDs, unsupported arities, foreign indices, or a missing
or inconsistent server SHA header. Both XYZ/UV source hashes are compared.

## Executed local preflight

- Prior regression 201 Python tests, including actual VTK with a working
  local context, passed before changes.
- After R1.1/R2 changes: **209/209 Python unit methods PASS** (eight new
  transport methods); original fixture corpus 10 positive / six negative PASS.
- Four new browser tests written for wire transport, linked selection,
  camera persistence, filter stability and cross-model recipe rejection.
  These require actual Chromium CI and are **not** asserted as locally executed.
- Local, invented regular-QUAD wire sizing (not APMesh generator data):
  1,000 cells: 38,426 binary bytes vs 75,633 compact JSON;
  50,000 cells: 1,857,859 binary bytes vs 4,065,167 compact JSON;
  500,000 cells: 18,524,036 binary bytes vs 43,633,825 compact JSON.
  Timing is environment-dependent; measured in a separate, explicitly synthetic
  output receipt. These numbers are not measured browser load or GPU frame rates.

## Required closure gates

- CI exact-head Linux Python/VTK, Windows scientific Python, Chromium build and
  actual vtk.js picking/camera tests. The GitHub CI result will be recorded
  after the exact commit executes; do not pre-declare success.
- R2 does **not** yet close: no 50k/500k interactive FPS, source-model scaling,
  GPU memory, streaming, LOD, large OBJ import, cross-platform browsers, or
  Windows physical GPU workstation qualification. The render data currently
  materialize JavaScript nested arrays after decoding; future incremental
  streaming/typed-array rendering remains necessary.
- Real multi-patch/nonmanifold provenance, actual generator event timelines,
  accepted adaptive epochs, all-QUAD and anisotropic source cases remain open.
