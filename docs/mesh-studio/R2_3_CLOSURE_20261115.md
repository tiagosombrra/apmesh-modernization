## Scientific and engineering constraints

- Render vertices are prepared into `Float32Array` once per geometrical object identity instead of using an intermediate flattened JavaScript array. Direct `Uint32Array` cell connectivity and `Uint8Array` cell colors are cached for each 2-bit TRI/QUAD visibility mask. The `WeakMap` cache does not persist after the dataset becomes unreachable. Original source mesh metrics and OBJ bytes are not modified.
- Rendered cell IDs always map to the original source face IDs. Selection overlay uses a source-ID index instead of scanning every face. No topology or patch ownership is inferred from common coordinates.
- Only genuinely planar UV chart scenes with <=150,000 valid triangular/convex quadrilateral elements are eligible for a bounded 2D spatial index. On overlaps, concavity, invalid camera transforms or unsupported input, `vtkCellPicker` is used instead. This does **not** certify a global source UV atlas or a continuous Jacobian.
- The same face (original source face ID `23738`) was selected at the same pixel with unchanged camera in one hosted Chromium run; the spatial index evaluated one candidate face. The synchronous calls measured **0.5 ms** (UV spatial index) and **204 ms** (native VTK picker). These observations cannot be extrapolated to global average/p95, long sessions or different GPUs.
- Data are **50,000 synthetic QUAD**. Not scientific generator C++ performance, not multirun statistics and not proof that 500k cells are interactive. No lossy face-thinning LOD was introduced, since that would leave holes or alter scientific face correspondences.
- The original stage's source-qualified P1 and four unaccepted candidates remain unchanged; source adaptive accepted epochs = 0.
