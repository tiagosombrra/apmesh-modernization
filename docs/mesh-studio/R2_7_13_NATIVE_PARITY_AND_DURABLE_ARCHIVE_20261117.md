## B. Source-identical real native C++ OFF-versus-ON protocol

`tools/mesh_studio/native_lineage_parity.py` and
`tools/mesh_studio/test_native_lineage_parity.py`
establish a **fail-closed** experimental protocol:

1. Compile the original research serial
   `quad_generator_outcome_probe` twice from the **same Git commit**
   and C++ configuration, with MPI/OpenMP/LTO disabled:
   `AP_MESH_ENABLE_RESEARCH_LINEAGE=OFF` for the control and `ON`
   for the experimental build. The numerical generator and native
   `AcceptedMeshScope` acceptance gate are otherwise unchanged.
2. For **each original article config** (`eistute`, `book`), run
   both binaries **sequentially in the exact same disposable output
   directory**, which is **fully removed and recreated** between runs.
   This ensures identical original absolute `OUTPUT_PREFIX` values in
   all emitted scientific files. The config is byte-equivalent
   (same exact original source and path relocation). No generated
   state or prior file survives the control run.
   Do **not** alter adaptation thresholds, budgets, or source patches.
3. The control run explicitly has no research lineage environment
   variable and must write **no sidecar**. The instrumented run
   has an explicit local `APMESH_RESEARCH_LINEAGE_DIR`; require a
   complete, source-validated native acceptance sidecar for
   **each** actual accepted global TRI event.
4. Compare full `real_generator_outcomes` markers **exactly**,
   including committed versus restored decisions, budget/growth
   outcomes, local selected UV captures, epoch count and
   bounded-log truncation status. A changed decision **fails**.
5. Discover all `*.obj`, `*.pos`, `*.csv`, `*.json` scientific
   outputs in each workspace **excluding only** the explicitly
   separate research-lineage directory. Require equal file sets
   and **identical raw file SHA-256 and lengths**. Missing original
   OBJ, metric CSV or incidence JSON **fails**. The only named
   `*_runtime_summary.csv` is excluded as an explicit
   **runtime-timing** record, not a scientific metric; unstructured
   debug `.log` files are likewise separately classified. This
   avoids approximate tolerances masking small but real geometric
   or scientific metric regressions.
6. Do not compare `stdout`, `stderr`, unstructured debug logs
   or wall-clock measurements byte-for-byte: different executable
   paths, capture status lines and elapsed timings are expected.
   Their exclusion is **explicitly declared**, not hidden.
7. Save original source config/input SHA, both executable SHAs,
   all scientific file SHA-256, native event marker and
   actual observed accepted-face counts to per-model JSON
   evidence (not a synthetic speedup benchmark).

The workflow `.github/workflows/mesh-studio-validation.yml` runs
the parity after both original native-source capture verification jobs
using a separate default-OFF CMake build, on the Linux CI host.
Independent Linux and Windows complete Python scientific regressions,
along with the Chromium UI suite, remain separate required gates.

Run from the repository root:

```bash
cmake -S . -B build/r2712-native -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=ON -DAP_MESH_USE_MPI=OFF -DAP_MESH_USE_OPENMP=OFF \
  -DAP_MESH_ENABLE_LTO=OFF -DAP_MESH_ENABLE_RESEARCH_LINEAGE=ON

cmake -S . -B build/r2713-default-off -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=ON -DAP_MESH_USE_MPI=OFF -DAP_MESH_USE_OPENMP=OFF \
  -DAP_MESH_ENABLE_LTO=OFF -DAP_MESH_ENABLE_RESEARCH_LINEAGE=OFF

cmake --build build/r2712-native --target quad_generator_outcome_probe --parallel 3
cmake --build build/r2713-default-off --target quad_generator_outcome_probe --parallel 3

python -m tools.mesh_studio.native_lineage_parity \
  --exe-off build/r2713-default-off/bin/quad_generator_outcome_probe \
  --exe-on build/r2712-native/bin/quad_generator_outcome_probe \
  --root . --model eistute --out-dir build/r2713-parity-evidence

python -m tools.mesh_studio.native_lineage_parity \
  --exe-off build/r2713-default-off/bin/quad_generator_outcome_probe \
  --exe-on build/r2712-native/bin/quad_generator_outcome_probe \
  --root . --model book --out-dir build/r2713-parity-evidence
```

**First real parity attempt:** [CI #44147253315](https://github.com/tiagosombrra/apmesh-modernization/actions/runs/44147253315)
correctly failed on raw `eistute_compatibility_summary.csv` mismatch
because that original C++ scientific summary explicitly includes
`OutputPrefix()` in its first `model` column: comparing different
absolute directories artificially changes the record without changing
geometry or a numerical metric. This cause was confirmed in
`GeneratorAdaptive::WriteCompatibilitySummary()` itself, not guessed.

**Correction:** the two build variants now run serially in the **same
clean temporary directory**, fully deleting the first run's data after
recording all its hashes, so the complete `OutputPrefix()` string
is byte-identical and no CSV field needs to be normalized or hidden.
The specifically timed `*_runtime_summary.csv` remains explicitly
excluded. A new regression test asserts this exclusion.

the accepted/rejected events or **any of the 38 compared scientific

This is stronger than matching only mesh counts, but is **not**
proof for every model, numerical backend, OS, physical GPU mode
or adaptive stage. Source face IDs remain snapshot-local and
R2.8 cross-epoch scientific LOD remains BLOCKED. Do not declare numerical parity until the
`R2713_NATIVE_OUTPUT_PARITY` markers are observed in a successful
job for **both original models**.

Scientific limits remain unchanged: physical GPU present latency,
RSS/VRAM, two accepted native epochs per model, validated
interepoch face/curve descendants and continuous error bounds are
**OPEN**. No default visualization picker promotion, source
acceptance threshold relaxation, C++ numerical change, merge,
release or tag is permitted by this protocol.
