# Mesh Studio R2.6 — bounded synthetic XYZ picking + complete source-face partition

**Date:** 2026-11-16. **Parent Studio branch head:** `a449eda521f0d0128bcc0efa22e5899df92517fc`.

## Implemented and explicitly restricted

- `xyzSyntheticRayPicker.ts` qualifies only the exact 500,000-QUAD local synthetic structured heightfield (zero placeholder SHA, `NOT_APMESH_SOURCE` ownership, strict connectivity and complete grid bounds). It uses a 2D grid ray traversal plus native triangle intersections to recover an *original* face ID from a 3D camera ray; nontrivial edges/corner ties and unsupported ray conditions return **ambiguous**. Any ambiguous result, miss or unsupported geometry falls back to `vtkCellPicker`. It is **not** a generally qualified spatial index for real, non-manifold or irregular APMesh meshes.
- This index is created lazily on the first eligible 3D click to avoid affecting first-frame times. That first call includes qualification time. Tests must compare both methods on the same view, camera and pixel; do not claim a reproducible speedup from a single call.
- `sourceLodLineage.ts` builds and validates a **complete, disjoint partition of original source-face IDs** into synthetic 8×8 grid groups. It rejects duplicate, foreign and missing ownership, verifies every source face is represented exactly once, and records group offsets in compact typed CSR arrays. This is only an aggregation/mapping contract: **no lower-resolution geometry, no Hausdorff/normal/metric error bounds, no scientific LOD and no new patch claims**. It cannot be used to calculate mesh quality.
- The existing R2.5 sparse preview remains **incomplete**, with holes; it is not silently rebranded as LOD.
- A local benchmark control audits full original-face coverage; the viewer never replaces real source geometry with these synthetic groups.

## Validation gates

1. `npm run test:contracts` checks 500,000 face identities, rejects duplicated/foreign IDs, validates synthetic-only qualification, edge fallback, and direct original-face ray picking. On a development workstation, this may use Node 22.
2. Browser regular test checks identity mapping without requiring GPU stress. 500,000 native/fast picking requires opt-in `APMESH_R26_500K=1` in a dedicated workflow, exports an original JSON receipt and tests source ID equivalence on an unchanged camera/pixel.
3. Linux/Windows Python source engine regression remains mandatory and must run unchanged.
4. **NOT QUALIFIED:** real APMesh 500k XYZ picking, Windows hardware GPU, true geometrically simplified LOD, real multipatch source lineage, anisotropic generator method, total process RAM/VRAM.
