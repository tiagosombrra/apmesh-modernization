## Resolved source evidence and explicit gaps

1. **`rechoir@0.6.2` — legacy source declaration found.** The source V5.6 lock had no modern npm `license` field, not evidence of unlicensed software. The installed `rechoir@0.6.2` `package.json` supplies a *legacy* `licenses:[{type:MIT}]` declaration and the installed package includes `LICENSE` (**1,056 bytes**, SHA256 `55d982a7adf646503ff21d0de490091d6d74a9f3447ba6959bf4fbd9ee7385ae`). Independently the official [`gulpjs/rechoir` release tag `v0.6.2`](https://github.com/gulpjs/rechoir/tree/v0.6.2) resolves to Git commit `340ad97a3c77ea27b0ac60fc37b3edcb494812b0`, with an original MIT license file and legacy MIT `licenses` metadata. **MIT is strongly evidenced for this particular version; actual source-tag bytes versus installed tarball LICENSE bytes are not yet claimed byte-identical.**
2. **Other npm priority paths** were actually installed, with a license file: `argparse@2.0.1` (declared Python-2.0), `caniuse-lite@1.0.30001826` (CC-BY-4.0), `pako@1.0.11` (MIT AND Zlib), `spark-md5@3.0.2` (WTFPL OR MIT), `lightningcss@1.33.0` (MPL-2.0). A declaration plus file receipt does **not** establish distribution compliance or that all material notices are complete.
3. **Three installed npm package folders lack a detected license/notice file:** `@rolldown/binding-linux-x64-gnu`, `@rolldown/binding-linux-x64-musl`, `seedrandom`. Do not treat the lock declarations or the absence of local files as a legal determination; verify the exact installed package/archive and its obligations.
4. **Critical deployment review — PyMuPDF 1.26.7.** In all three installed Python profiles the actual distribution metadata states `Dual Licensed - GNU AFFERO GPL 3.0 or Artifex Commercial License`; a license file was captured in each. This matches the [version-specific PyPI record](https://pypi.org/project/pymupdf/1.26.7/) and [official PyMuPDF licensing explanation](https://pymupdf.io/licensing). **Do not ship PyMuPDF as an unreviewed proprietary product dependency.** Determine whether it is confined to offline academic CI/PDF auditing, independently evaluate AGPL duties for the intended deployment, or seek licensed/replacement alternatives. The source-verified C++ accepted TRI and V5.3 vector PDF evidence do not require a blanket production license assertion.
5. **Do not merge platform profiles.** In the actual Python PDF-only profile, `numpy==2.5.5` and `Pillow==13.0.0` differ from API `numpy==2.3.5` and `Pillow==12.3.0`. The source locks deliberately identify these differences. The per-profile totals are **79 records**, not 79 distinct packages bundled in a single program.
