# Mesh Studio V5.2 — prospective original-native accepted TRI vector-publication contract

**Registered before any new exporter is written or exercised**, 2026-11-20, isolated research PR #239. Product-engineering artifact, not a new native mesh experiment or an amendment to AFT acceptance/thresholds.

## Question and source admission

Can original source-accepted C++ Eistute and Book TRI snapshots, and only these snapshots, yield reproducible, source-traceable and fully vector per-patch UV article figures with original native triangle face keys, original source curve/sample labels and no false node welding or adaptive LOD claim?

Source MUST be the **same-run retained original** `build/r2712-native-evidence/` from compiled original GeneratorAdaptive: real C++ per-face postcommit NDJSON and model-specific original source/acceptance JSON digests. The existing independent `native_accepted_scene.generate_original_scene_bundle(directory)` must be rerun inside the export operation; it validates the original C++ retained raw files and audits source/face/patch/curve correspondence, not a freestanding uploaded visual JSON. No source path from HTTP or browser is accepted as original native evidence. The previous independently validated `build/r2720-native-accepted-scene.json` must agree **exactly** with the newly derived canonical scene (including SHA and all original face/corner keys); if it differs, export MUST fail closed.

## Bounded vector methods

One `SVG` per truly accepted native scene (current original Eistute step1 and Book step1), with deterministic fixed physical dimensions (e.g. Eistute 178×120 mm and Book 190×160 mm), each of the source's 4 or 28 original patches in a **separately labeled local UV panel** (not welded in one invented atlas). Every original accepted native TRI face is drawn once as an SVG vector polygon, using the source's **three actual original per-corner UV double coordinates**; every SVG face carries original `model`, `accepted_step`, `patch_slot`, `native_patch_id`, `element_slot`, `native_element_id` data. Its panel count and per-patch polygon count MUST match the original source exactly. Source shared-curve sample vertices may be shown as *markers only*, and only where an independent original native face contains the same `(patch_slot,native_node_id,xyz)` sample; no sampled-chord interpolation or physical welding may be asserted. Fonts must be standard system fonts, not remote dependencies; no bitmap/image, `script`, `foreignObject`, stylesheet href, inline event handler or external URL allowed.

A machine-readable figure `manifest.json` must contain schema/version, figure hashes and sizes, exact original NDJSON SHA, original CAD model/config SHA from the R2.7.19 identity record, scene/accepted step/patch/curve count, selected face identity schema, source sampled-curve and per-patch face inventory, original committed epochs, and explicit `physical_node_welding_certified=false`, `cross_epoch_face_lineage_certified=false`, `scientific_lod_qualified=false`. Source preview in the Web Study Workspace, if added, MUST not substitute a browser-only forged manifest for the real original source-C++ audit. A figure is **2D patch-UV vector** only, not a vectorized 3D surface, a quality heatmap, proof of source parameterization continuity or physically welded seam.

## Negative controls and admission gates

1. Genuine source C++ same-run Eistute/Book output is admitted **only after** independent `native_accepted_scene` revalidation. Tampered original accepted NDJSON bytes, altered original face or patch ID, missing source report or foreign/missing curve incidence must be rejected. A JSON with forged `scientific_lod_qualified=true` must fail.
2. Geometry invariant: all accepted source TRI are drawn exactly once, original per-patch face slot inventory and IDs preserved. Reject nonfinite/out-of-bounds UV and repeated/native face keys; do not silently drop invalid triangles or collapse shared node IDs between patches.
3. Figure byte reproducibility: same source records + renderer version produce identical SVG/manifest SHA/bytes, with fixed numeric/locale formatting and no machine paths/time stamps. Independently scan SVG XML for prohibited raster/active/external elements and check original face counts/panel counts.
4. Integration test: same-run CI builds both original C++ models, exports from the raw native accepted source, stores source-attested figure artifact and independently audits manifest+SVG face keys. Browser native accepted-scene panel should offer a clear source-bound way to open/export these figures without granting unverified uploaded files scientific source certification.
5. No change to original C++ acceptance threshold or default VTK; no merge, release, GPU claim or R2.8. If any original model fails, record actual negative and keep next product gate **OPEN**, not synthetic success.

**Stop condition:** after a reproducible source-certified figure for each actual accepted step-1 Eistute and Book, do not add another research-only C++ observer. Focus on Study Workspace integration, independent reviewable PR slices and lockfile/CI efficiency.
