## Work-item admission and execution rules

Before a task, record its closure row, concrete output, supporting failure or
coverage gap, minimal affected checks and stop decision. Deliver an implementation,
a newly measured required contract, or a decision that changes the dependency
queue. Another anchor count, green unchanged suite or source-only PR does not by
itself satisfy this progress requirement. Code is changed only for a justified
defect/engineering need; green regression is not a reason to invent a repair.

Keep focused checks during edits. Run full required regression on the exact
delivery head and merged main; preserve and reuse identical-revision successful
evidence rather than rerun it without a change. Reopen a large instrument/science
campaign only for a changed dependency, named required missing gate or a recorded
failure with a justified controlled response. Existing frozen artifacts and
negative controls remain required within their scopes.

One failed/refused calibration is retained and classified before any retry. A
changed fixture must re-establish admission first. No forced selector result,
disabled check, altered tolerance or manufactured graph obtains coverage. A
blocked experiment stays unqualified while an independent closure obligation can
proceed. Scientific proposals retain separate advisor-alignment requirements.

After each package, report obligations resolved, production change or newly
qualified caller, remaining blockers and one next implementation. Do not use PR,
test or numbered-slice counts as a percentage or effort estimate.
