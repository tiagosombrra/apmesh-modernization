# Owned serial synchronization, reconstruction and diagnostics

Classification: engineering-only caller/configuration change supporting S3-05
and the bounded stage 6 engine boundary. Entry main is PR #152. GenerationContext
optionally owns SerialFlowConfig: shared-curve synchronization, hybrid mode,
runtime summary, adaptation debug and literal template mode. The factory samples
already-applied process state. ApplyRuntimeConfig retains the existing projection
of hybrid-off to template n. Raw typed modes are not normalized again. Parser,
validation, defaults, CLI transcript and scientific policies remain unchanged.

The generator reads immutable raw settings; this group has no stable-mode writes.
A bounded helper retains the original synchronization guard at its original slot
and calls the unchanged graph cloning/adoption operations. Diagnostics retain
their original zero/truth predicates and output formats. Adapter receives an
explicit debug input for its existing writer. Its existing context observer
supplies a template string copied into each front independently of AFT settings.
The original exact y comparison stays in the same execution phase. Missing flow
settings and unconfigured standalone fronts retain live global reads.

Template copying may allocate before execution. ConfigureAdvancingFront therefore
propagates ordinary exceptions; the already-constructed front retains its existing
RAII teardown. The front owns its optional string without an application-module
dependency and can outlive the generator. No allocation-free, same-generator
recovery or broader failure guarantee is introduced.

Four cases in the existing native metrics probe check scalar/string capture,
source mutation/retirement, conflicting globals and identity-only fallback. Actual
shared-curve graph changes on the existing native two-patch model must match the
legacy path and differ from foreign controls. Runtime/debug file presence and
compatibility/runtime metadata must follow owned flags; Adapter debug must use
the same value. Template modes include y, n, empty and a 192-character non-y string.
Four fronts retain the literal mode after generator destruction, while unconfigured
fronts follow later global updates. These output checks measure gates/metadata;
the unchanged frozen reference supplies full-generation scientific comparisons.

Require exact-head/main C++17 GCC/MSVC builds, 75 CTest/385 nested Python controls,
all prior native markers, nine scientific states/45 exact artifacts/123 boundary
comparisons and real MSVC invalid/analytic CLI controls. Source reversal restores
the complete generator/Adapter/AFT bodies modulo explicit settings, the same sync
guard and debug writer argument. Exact template literal/phase, report formats,
parser/apply/defaults/hybrid projection and other production remain unchanged.
Analyze actual canonical production compilation commands once each plus the
existing probe with unchanged flags. Explicit formatting is independently token-
checked. Whitespace, inventory/contracts, staged identity and remote gates remain
required. No scientific model, target or instrument campaign is added. The
[compact record](stage3/serial_flow_context/summary.json) and local
build/serial-flow-context reports retain commands and identities.

This closes the named flow-control group only. Milestone consolidation must still
delimit remaining shared precision, counters, timing, rank/thread/runtime state
and exit obligations. Calls remain serialized. Stage 3/6, reuse/recovery,
concurrency/parallel and whole-process memory obligations stay open. Consumers
must rebuild after layout changes; no external ABI guarantee is introduced.
