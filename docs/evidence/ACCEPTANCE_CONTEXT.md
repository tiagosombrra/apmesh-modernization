# Owned generation acceptance controls

Classification: engineering-only caller/configuration change supporting S3-05
and the bounded stage 6 engine boundary. Entry main is PR #150. GenerationContext
optionally owns the remaining 26 AcceptanceConfig values for scoring, growth,
quality/error thresholds, small gains and efficiency. The factory captures
current process values; parser, validation, defaults and ApplyRuntimeConfig stay
unchanged. Consistency-related acceptance settings retain their separate group.

This group has no stable-mode assignments. The generator reads the raw owned
value without a separate override copy. Missing settings retain live global
reads. Scalar getters supply every original arithmetic/comparison/report use,
including poor-ratio targets used during patch refinement. The growth penalty
receives five explicit inputs through a member wrapper at its three original
call positions. Linear/quadratic formulas, soft-limit order, short-circuit
acceptance decisions and scientific literals remain unchanged. No criterion,
clamp, normalization or scientific policy is added.

The existing native metrics probe checks three cases: 66 exact double
representations including signed zero, four integer fields, source mutation/
retirement and foreign-global negative controls. Thirty actual growth-penalty
outputs compare step 1 and later-step branches across growth below/at/above one,
soft-limit cases and linear/quadratic modes. Six real accepted/rejected reports
must show the owned acceptance mode while foreign globals stay unchanged.
These report labels verify output; accepted/rejected generation decisions use
the existing frozen nine-state scientific reference.

Require exact-head/main C++17 GCC/MSVC builds, 75 CTest/385 nested Python controls,
all previous native markers, nine scientific states/45 exact artifacts/123
boundary comparisons and real MSVC invalid/analytic CLI controls. Source reversal
restores the complete generator body, growth formula and three call positions
modulo explicit input/accessor bindings. The initial local reversal matched an
accessor suffix in ConsistencyAcceptanceMode; whole-identifier matching corrects
that driver without production/oracle changes, retaining the refusal. Analyze
each actual production compilation command once plus the existing probe with
unchanged flags. Explicit formatting is independently token-checked; whitespace,
inventory/contracts, staged identity and remote gates remain required. No new
model, target or instrument campaign is added. The [compact record](stage3/acceptance_context/summary.json)
and local build/acceptance-context reports retain commands and identities.

Formulas, order, synchronization, quadtree/templates, selection, reconstruction
and acceptance/stopping policies are preserved. AFT/runtime globals and mutations
remain shared and serialized. The existing reference is bounded evidence rather
than a complete acceptance parameter matrix. Stage 3/6, reuse/recovery, concurrency/
parallel and whole-process memory obligations remain open. Consumers must rebuild
for layout changes; no external ABI guarantee is introduced.
